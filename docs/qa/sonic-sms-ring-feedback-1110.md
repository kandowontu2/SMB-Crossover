The source-only proposal adds visible ring sprites, a two-digit ring count, acquisition sparkle, and the type `$55` thrown-ring sprite to the authenticated raw43 draw row. Its parent is exact `a20d254d4730583ee1f039b10abcf873559987e4f989968037a38e17427faac1` with the verified `dcd1640b` contact changes. The proposal preserves the DK Jr. changes, Jay’s proposed pages 331 and 332, and the original ring-contact page 333. Sonic’s existing physical CHR page 224 holds 24 new 8×16 pairs. The original body and menu portrait pairs at tiles 0, 2, 32, and 34 are byte-identical. The checker reconstructs the entire previous page from the pinned donor and previous atlas recipe before replacing any pairs. The artwork comes from the donor’s packed common and Green Hill sprite data, the original ring tile data, and source Sonic frames `$1C/$1D` used by type `$55`. This includes both HUD label sprites, digits 0–9, both pickup sparkle forms, and every populated pair of the six drop poses. The NES uses its existing ground sprite palette 2 for the color conversion. The fixture world rings use one full-width donor pose. The new body page SHA-256 is `f1abc48428222522bc09988d9164a5ae95ee90b580fc82fd791b2d16bd03cfb0`.

The draw code uses 518 bytes in a proposed tenth typed row at bank 2 `$D800..$DBFF`, backed by physical CHR334. Its source page equals canonical fairy page 320 before composition and depends on the existing Zelda II alias. The code retains the prior motor and damage dispatch and reuses the body renderer’s three scratch bytes after its four original sprites. The count sits below the native HUD split. World ring visibility follows the actual pickup bits, with the five positions split across alternating display groups to cap each group at three rings. The pickup sparkle lasts six committed source updates, matching the donor’s display lifetime. The drop uses the source record’s active sprite pointer and pose. The donor’s blank drop halves leave no OAM entries. Existing OAM rotation applies to every emitted sprite. Capacity checks reserve a whole ring before drawing its two halves.

The ten-row loader reads back both extensions before publishing either header. An actual cold load took 22,486 PPU reads with a minimum stack pointer of 187. Warm loading used zero reads. All three injected faults on row ten rejected, and the other six typed owners matched their exact current cold results. The directed CPU test verified all 100 BCD counts, rotating and unrotated body and world OAM, and six buffer-capacity boundaries without logical pointer wrap or writes outside the allocated OAM slots.

The actual current Sonic menu portrait retained all four exact sprite entries and page 224 after regular NMI. Both facings of the existing Zelda II pose 26 retained the current canonical page 320 and identical presentation. Undoing only that table entry in either facing caused an actual page 334 publication, which demonstrates the alias dependency.

The actual 130-iteration native Main/NMI replay published all six values from `00` to `05` and returned to `00` on the same tick-120 Goomba contact. It issued 130 HUD draws, 20 world-ring draws, 27 sparkle draws, and 30 nonblank type `$55` draws. All 130 NMI checks latched page 224 and read the expected sprite palette values `$16/$30/$27`. Sonic kept both lives, released stun at tick 156, resumed by tick 178, and the drop expired at tick 208 after 81 source updates, matching the frozen contact replay.

The authenticated row 2 interrupt test passed 481 screen-enabled lag NMIs and 481 scanline IRQ cuts across the new renderer, plus one nested IRQ at stack pointer 181. OAM, registers, private RAM, live stack, mapping, and the foreground continuation were exact in the populated and capacity-limited cases.

This is a source and CPU proposal with the existing five-ring fixture in SMB 1-1.

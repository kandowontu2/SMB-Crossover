# Sonic SMS ring acquisition and hit onset

The portable 6502 adapter reads a donor ring tile at the source actor’s `(X+12,Y+8)` probe, checks the original vertical scroll gate, and clears one of the tile’s two ring bits. It returns the replacement tile to its caller and publishes the original sparkle position and six-update seed. Packed BCD awards use the donor’s `$01` and `$10` operands, 100-ring rollover, life increment, and sound cue IDs.

The hurt entry handles the original drop, stun, star, and shield flags separately. A ring-bearing hit clears the full BCD count, writes the original type `$55` spawn fields into the first available record, and applies the original 24-bit knockback. A full pool still costs the rings and starts stun. An unprotected zero-ring hit produces the original death-onset flags, vertical speed, 96-update timer seed, and music cue. The adapter preserves the preexisting bytes in the supplied free record wherever the donor writes none.

## Verification

`tools/audit/check_sonic_sms_ring_adapter_1110.py` executes the assembled 6502 leaves against the pinned SMS donor (`6ad738965ece231427ee046b9905cfee470d5c01220afdd934da4673e4a2458b`). It covers 600 BCD awards, 1,056 tile/scroll/page cases with 220 additional re-queries, and 288 damage cases. Rejected pickups and blocked damage write only the test call stack. The adapter is 394 bytes with a 56-byte explicit test context, including one 26-byte donor-format drop record. Maximum measured times were 52 CPU cycles for the award, 191 for acquisition, and 214 for damage onset. It uses no zero-page state.

The donor’s actual `$0A10` unpacker consumed the 2,110 compressed bytes named by the Green Hill Zone Act 1 header. It produced a 256×16 tile map with SHA-256 `eaf6efaa409f9331ae32a93224ace3a5afe5b25d7ed62bdbdb103052c75b36f3`. The 128 visits to both halves of 64 authored ring cells acquired 107 rings, exhausted the corresponding bits, and left BCD `$07` and three lives from an initial two. The test supplied those visits in map order.

The host replay reconstructed exact `49295acff1d70349119b599882a2ec0b4e2f58d21f153c90b2228dc9aceee2a7`. It used the existing controller-only earned mushroom and Goomba route. The observer read 419 committed source positions from raw43’s ordinary `HostProject` entry and checked both authenticated headers against `a72b0194a989064ae62ef75a04986523`. The separate ring fixture copied three literal Green Hill cells, `$7A $7B $7B` from row 5, columns 82–84, to row 5, columns 6–8 on an isolated plane. Committed Sonic positions naturally collected five rings at X203, X212, X230, X245, and X260, all Y176. The three fixture tiles became `$78 $78 $78` after 25 queries. The original Goomba contact at Sonic X678/Y176 and Goomba X688/Y184 reached real `ForceInjury`. Applying the same contact to the isolated adapter dropped BCD `$05` to `$00`, set stun `$40`, set X/Y velocity to −512/−1,024 subpixels per update, and initialized one type `$55` record with vertical velocity −1,024. The observer wrote only its separate fixture state and used the same controller input as the existing route.

## Integration boundary

The fixture placement and all adapter state belong to the test. Live ring placement, HUD, sparkle rendering, sound mapping, actor updates after type `$55` spawn, stun recovery, and death/restart remain separate work. The original thrown-ring update and stun recovery are traced in `sonic-original-rings-hurt-1110.md`. For a live bridge, acquisition belongs after accepted X/Y contacts and before the donor’s damage-animation and sparkle update. A separate hit route must preserve the source attack, shield, and immunity decisions and define how source death enters the host’s scene lifecycle. The current native mushroom and injury path remains active.

The 394-byte adapter exceeds the 225-byte unused Sonic metadata extent by 169 bytes before placement, hooks, or effects. A live integration needs separate code and state ownership and an authenticated caller. The source-only CPU replay emitted one stdout receipt and created zero build files.

## Reproduced defect and cause

Review of Mario's Hard route exposed letter-like body tiles during shrinking.
Actual direct PPU955 captures reproduce them in both parent OJ and OV; they are
not an asynchronous screenshot artifact or a new shallow-router regression.

The authenticated original SMB3 PRG029_D224 code reverses the growth index when
shrinking, then saves that final index's parity before drawing. The port chose
its frame using the reversed index but chose its graphics bank using the raw
unreversed timer. All shrink phases consequently selected the opposite bank.
Ordinary form/frame bank checks did not cover this separate transition override.

The repair derives the same zero/nonzero phase from the final native frame:
39 is every odd index, while 11/14 are even. Its bit5, shifted twice, supplies
the existing zero/nonzero private-scratch test for both animation directions.
Two operand bytes change in M3Graphics. No instruction address/count, art,
palette, RAM allocation, motion, weapon, audio or other ROM byte changes. A
corrected branch can take four more/fewer cycles; complete CPU timestamps are
not asserted identical.

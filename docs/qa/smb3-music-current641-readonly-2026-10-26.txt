BOUNDED A-WINDOW LEASE: FEASIBLE CONTRACT, NOT IMPLEMENTED

The steady translated core executes in C38. Its A86 cold bridge ends with a
tail JMP into C before data readers run. The current resident IRQ uses no
A-window code/data and performs no5115 write. Those facts make a bounded
full-source-call A lease plausible, subject to actual interrupt proof:
  1. Enter a resident/C helper after the cold A bridge has relinquished A.
  2. Keep CurrentBank, the foreground shadow, literally unchanged. Track any
     temporary data-bank selection in owned adapter metadata if caching it.
  3. Map the requested intact source page into A; keep it until another page
     is required. All active code and return destinations must remain C/fixed.
  4. Restore the saved foreground hardware-A mapping before host return,
     ExpandedAudioDecoded/CrossoverGraphicsBank, or any A-resident mixer call.
  5. Prove IRQ at each instruction boundary, all NMI return/bank ownership,
     original A/X/Y/P/SP, source pointers and every ordered source store.

Important correction to the old report's shorthand: B3ReadAddress reads
CurrentBank and later writes that value to5115. It does NOT read the physical
mapper bank, and BankPRGA a is only STA5115; it does not update CurrentBank.
The isolated core fixture deliberately sets hardware A and CurrentBank to86.
That equality is a fixture contract, not a proved host invariant during a
lease. An integration must not overwrite CurrentBank to make the adapter
appear correct, nor assume reading5115 yields the prior mapping. The outer
ExpandedAudioUpdate already saves its foreground CurrentBank and restores A
on return; exact driver/helper ownership still needs to be established inside
that boundary. No lease implementation or guaranteed saving exists yet.

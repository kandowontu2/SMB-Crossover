# Sonic: four-state Mr. Gimmick family

This is a source-only menu component, not an installed nightly. Downloads
`6d83dea872b42cd39c14d756334a801c8f7da7dfa63ecea16d9f13835c63638d`
still exposes the temporary Mario-family Sonic prototype at Select10.

The new family is **Mr. Gimmick → Bub → Bob → Sonic**, selected with Select
on the existing Mr. Gimmick slot. Sonic resolves to distinct raw character43;
the retired Mario10 proxy is removed from the legal Mario cycle. All100
distinct names remain reachable and start-confirmable.

The source reuses the original214-byte navigation lease,32-byte pending shim,
40-byte Sonic name gate and85-byte color gate. The cursor-high expression
replaces CLC/ADC32 with OR32 after proving the intermediate range0..16;
saved status preserves the original carry behavior. The byte saved funds the
four-state resolver. The unchanged full cold initializer is relocated into
the retired Mario table10 byte, explicitly reserved Mike tail, retired
AltTail stub and its own old body. The sole same-bank AltTail caller is
retargeted to its original destination. No new RAM, PRG or CHR allocation.

`check_sonic_gimmick_frontend_1110.py` passes all1024 byte-Y/status cursor
cases,16 complete native cold-initializer comparisons,100 old selector states
covering99 other names and600 Start/A/direction input comparisons. Registers,
application state, PPU contents and CHR mappings match the parent in those
unchanged cases. These are CPU tests, not Mesen presentation evidence.

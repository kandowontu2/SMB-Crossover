Current Mario0 versus Luigi8 movement: source/assembled-CPU comparison
2026-10-26. Documentation only; no game changes or additional native run.

Conclusion: Luigi is a modestly modified native SMB player, but current Mario0
uses a different Crossover movement engine. Consequently Luigi is not current
Mario's physics with only a slightly higher jump and slightly less traction.
Several differences are substantial. The small Luigi constants themselves are
consistent with that stated intent relative to native SMB; the current dispatch
means they are being compared against a different Mario profile.

Intent assessment and finite recommendation
-------------------------------------------
The current implementation does NOT strictly meet "current Mario physics with
only modestly higher jump/slightly less traction." Luigi's current physical
item/Fire progression is separately native-qualified and no game bug is inferred
from a distinct projectile pool. The movement differences above are a separate
source finding, not a reason to discard the successful native item test.

If preserving that original intent takes precedence, a future private change
should share Mario0's selected Easy/Hard dry profile, then add only explicitly
bounded Luigi jump/brake changes. Simply sending SelectedCharacter8 into the
existing MarioSourceMovement is insufficient: its integration/gravity/water
helpers and several source behaviors branch on literal character0/8. Those
branches require a genuine profile contract and full controller/collision/IRQ
qualification, retaining actual Luigi identity/graphics/projectile owners.
No such patch, model tuning, installed-ROM mutation or extra native run is
included in this packet. ROOT can decide how to reconcile the original intent.

Timing-plan constraints, not a proposed/adopted patch
  Keeping rendering off until the existing full DMA/joy routine returns would
  enable display after visible line0 in these failures, changing HUD/IRQ timing.

  publication relative to visible fetches. Neither is qualified as a fix.
  A safe solution must retain complete queued writes and source audio, preserve
  atomic bodyCHR/OAM, title/level/lag behavior and physical line31 HUD split,
  and meet actual vblank/pre-render constraints at the worst supported packet.
  ROOT independently owns source/CPU timing analysis and must review a timing
  plan before this agent builds a source candidate. No body-art reorder yet.

# Oversized MMC3 selection repair

The full-roster MMC3 menu no longer reloads an entire character family's
graphics whenever the highlight changes. It uses a resident menu portrait
atlas for all 33 identities, with separate original poses for outlines on/off.
The ordinary transition into the menu still loads this atlas; confirming a
character restores that family's full gameplay graphics before level entry.
MMC5 and both standard 14-identity builds are unchanged.

## Causes and changes

The old controller-only menu walk produced 857 fully blank video frames while
browsing 33 identities. Family changes transferred tens of kilobytes with
rendering disabled. A dedicated 66 KiB portrait atlas now occupies CHR-RAM
pages 52–117 only during selection. Each highlight changes a bank number and
copies a complete portrait; it performs no graphics upload or forced blank.
The atlas uses original sprite tile bytes, OAM offsets/flips and colors captured
from the current MMC5 build. The extractor observes the actual MMC5 sprite-bank
registers $5120–$5127, including $5130 upper bits, then reads those CHR-ROM pages.
The ordinary PPU debugger view can select MMC5 background tiles instead; the
first prototype used that wrong view and was withdrawn after visual inspection.
The corrected checks also compare complete emulator-rendered screenshots,
independently of the tile decoder. No artwork was redrawn. The background grid and
its nametable remain exactly the same.

An intermediate version exposed another real timing problem: queuing all
four sprite palettes, the name, cursor and control hint together made OAM DMA
run into rendering. Every transition then had a hidden/corrupted sprite frame.
The final code queues the control hint on the following idle menu frame.
Palette, CHR and portrait OAM are published together inside VBlank. A pending
hint is encoded in the otherwise idle menu OAM-offset byte, avoiding additional
WRAM or native audio scratch ownership conflicts.

The MMC3 weapon-composite directory overlays inactive native sound scratch.
The NMI uploader now accepts jobs only for the 12 actual wide-art profiles
(2–13). Legacy sound bytes and the menu's invalid profile values cannot become
graphics-upload jobs. Menu portrait identity is stored as $80+index in the
existing cache-profile byte, rather than in scratch used by Contra/Link audio.
The Mario lag-frame exception also retains the previous completed CHR mapping
while the selection menu's next portrait is being assembled.

The port reserves PRG bank 247 for menu code/records and raw graphics pages
756–821 for the atlas. It remains a 2 MiB PRG / 256 KiB CHR-RAM cartridge.
Dead address-preservation NOP padding was removed to fit the resident NMI
guard; Bass's aligned DPCM payload remains at $F140. All calls are resolved
from the new linked labels. No gameplay physics or MMC5 source was changed.

## Current ROM recheck

`build/verification/mmc3-menu-final-recheck` contains a fresh run against the
published `build/smb-crossover-mmc3-oversized.nes`, with the same SHA256 above.
Both outline settings again pass all 33 source-pixel and complete rendered-screen
comparisons, 5,208 browsing frames, and the VBlank OAM DMA deadline checks. There
are zero blank browsing frames and zero mixed portraits. This check uses the
published ROM directly; it does not rebuild from the newer, unfinished roster
work in the source tree.

the same output can be checked for restored gameplay CHR and bank ownership.

`entry` subdirectory is not counted as a passing ROM test. The separate
`entry-mmc3` results retain the MMC3-specific boot, CHR and interrupt assertions.

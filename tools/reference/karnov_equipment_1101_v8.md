or Ladder in the native game, change the v7 option whitelist, grant a carrier,
or publish a nightly. The native whitelist remains Boots0/Boomerang3/Wings7.

The donor is `C:/NES/Karnov (USA).nes`, SHA256

## Entry and state contract

The include imports `KrState`, `KrPointer`, `KrSaved0`, `KrSaved1`, the exact
portable include generated by the recipe, and the callbacks below. The owning
link must already authenticate and map the correct private source state.

`KrState=$C000` covers original RAM `$0000..$07FF`. `KrPointer=$03` borrows only
host3/4; NMI0..2 is untouched. Each exported wrapper saves/restores3/4 using
`C7FE/C7FF`, returning source A/X/Y/P (apart from proven relocation-only pointer
register values). These wrappers must execute sequentially with the existing
actor/options/weapon wrappers. They must not nest: the two saved-pointer bytes
are one shared context, not a stack. There is no new persistent RAM or SMC.

The original58/59 used as temporary data by terrain/attribute helpers is private
`C058/C059`; it is distinct from the actual dispatcher pointer3/4. The CPU
comparison excludes only original58/59, original stack100..1FF, and the two
saved-pointer bytes; every other original RAM byte is compared. Pointer-valued
A/X/NZ differences are accepted only for the exact original C83C/C83E writers
and the proved original/relocated inline target. Callbacks and Y/C/V/D/I remain
compared. All host ZP, including3/4, is checked restored after every export.

Exports are `KrEquipmentBomb`, `KrEquipmentBombRender`,
`KrEquipmentBombBlast`, `KrEquipmentLadderGrow`, `KrEquipmentLadderRestore`,
`KrEquipmentLadderOverlay`, `KrEquipmentLadderRetract`,
`KrEquipmentLadderRebuild`, and `KrEquipmentOriginalRebase`.

`KrEquipmentOriginalRebase` is evidence for the original camera owner. It also
shifts the private player/enemy/object pools, not only the Bomb. It must not be
installed as a native camera hook that double-moves the actor. A native adapter
must rebase the Bomb anchor once at the actual scroll boundary.

## Exact Bomb behavior

Original option1 activation at EB19 uses ownership8F bit1 and BCD stockBB.
It requires actor state below7 and no active Bomb; it sets C0=80, C1=player63,
C2=player64, queues timer job2 with remaining2, and decrements stock with the
original BCD helper. The v7 source fixture executes that actual activation.

The Bomb is parked in world space. AE3D has no gravity, velocity or ordinary
projectile movement. It is removed when its screen anchor leaves X08..F7 or
Y20..BF. Original camera rebasing increments/decrements C1/C2 one pixel in the
corresponding direction. This component proves all four original rebase paths.

The original timer scheduler runs when0F&3F is zero, and processes one expiring
queue job per call. With the activation phase used by the source sequence, the
Bomb changes80->81 at accepted update128, ->82 at129, ->83 at145, and ->0 at161.
The first transition initializes C3=10 and requests sound12. The update function
owns the remaining two16-update explosion phases. This sequence uses the
accepted-update clock adaptation already declared by v7, not original wall
clock behavior under native lag.

The original renderer writes private source OAM0250..0257. The armed Bomb uses
one8x16 sprite (tile41/43 selected by E8 bit3); explosion phases use tiles45/47
or49/4B as two adjacent8x16 sprites. An armed call leaves the second slot as it
was; the legal source fixture initializes it hidden. Native OAM ownership and
CHR mapping are not granted by these tile numbers.

Blast contact requires an active explosion, then uses the original unsigned
32x16 rectangle against source enemy0652/0653. It applies original damage8,
the source per-contact bit20 guard, source HP thresholds at CDAD, original death
selector2, and the score event from CDED. All64 table entries are tested. This
is the original enemy pool contract; native SMB enemy enumeration/damage and
score publication still require an adapter.

On the final explosion tick C460 derives the world tile and the original
stage3/5/7/8 coordinate lists may enter source scene8, saving previous5E in071F.
The source predicates are preserved, including26 matching cases in the test.
These are original Karnov terrain scripts, not permission to alter SMB tiles.

## Exact Ladder behavior

Original option2 activation uses ownership8F bit2; it is reusable and has no
BCD stock. With no ladder it clears0624..063E, anchors0625 atplayerX and0626 at
playerY-8, saves the previous5E in071F, and enters source scene1. Existing ladder
activation requests source scene0B retraction. Original actor state/ceiling/
terrain restrictions and activation sounds remain in the v7 original fixture.
The original level-index3/6 activation may request C6FC; eight such callback
cases are exercised, but no native counterpart is claimed.

A4B6 adds one segment per source scene1 job. It stops at8 segments, Y<20, or
negative/01 collision. A successful segment writes collision class09 into the
source040C cache, saves original metatile and world coordinates in triples at
0627..063E, publishes BE/BF/BE/BF tile quad AD..B0, calculates AB/AC nametable
and B1/B2/B3 attribute packet, requests5F bit2, then moves the tip up10 pixels.
This is a background and climbable collision object, not visible platforms.

A5BD restores the top segment's exact metatile quad, collision class and
attribute palette. Source viewport clipping prevents offscreen publication.
The owning fixed-bank step then decrements0624. The ordinary retraction owner
returns ownership8F bit2 when empty, clears0624..0626, selects option2, requests
the HUD callback, restores source071F scene and follows the source draw/frame
continuation. The rebuild owner instead clears the27-byte object and starts
growth again at the current actor. B46F supplies the CF metatile override when
the original room cache rebuilds, preserving a ladder across offscreen reloads.

The CPU sequence executes actual activation -> growth [1,2,3,4,5,6,7,7] -> source
scene return -> retraction [6,5,4,3,2,1,0] and returned ownership. Native ordinary
actor updates must be suspended for those scene jobs in the same way as the
source; simply updating the ladder alongside ordinary movement is incomplete.

## Explicit callback and data boundaries

| Import | Original boundary and requirement |
| --- | --- |
| `KrEquipmentReadStage` | Replaces only five original `LDA ($4C),Y` reads. Read current-stage ROM at logical(C04C/C04D)+Y; preserve X/Y and C/V/D/I, return A and its NZ. May borrow3/4 within the outer wrapper. |

| `KrEquipmentHUD` | C534 selection/HUD event after final retraction. Original owning state and event arguments are preserved; native icon publication is not included. |
| `KrEquipmentScene` | C1C7 optional original scene event. Native equivalent remains required. |
| `KrEquipmentDraw` | DF61 original scene draw continuation. Native private packets must be rendered through the owning native VRAM/OAM service. |
| `KrEquipmentFrameGate` | C046 original frame continuation. The standalone test records this tail event and returns to its harness. Native integration must adapt scene scheduling, not jump to the donor's main loop. |

Callbacks are isolated identically for donor and relocation; that proves the
call arguments/order and surrounding state, not each omitted callback's full
implementation. The reader fixture is actual assembled code: original bank0
is loaded into flat test memory2000..3FFF and the logical8000..9FFF pointer high
byte is XORed withA0. This is a test-only flat address mapping, not native NES
PPU RAM or a host resource grant. It executes6,867 actual reads.

The compiled stage-cell index/table-class/palette data is explicitly bound to
original stage0 bank0. The remaining readonly tables are fixed source screen
rows, masks and enemy HP/score. A full native integration must supply current
SMB level metadata, saved metatile storage, climbable collision, VRAM/attribute
publication and scene scheduling. Static donor stage0 metadata is not a full
campaign implementation. Bomb OAM/CHR assets and native enemy hits also remain
to be adapted. No graphics resource grant is implied by this component.
